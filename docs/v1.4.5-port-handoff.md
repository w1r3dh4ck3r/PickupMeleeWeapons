## What This Mod Does

`PickupMeleeWeapons` makes AI troops pick up dropped melee weapons during battle. It patches three methods on `HumanAIComponent` using Harmony transpilers and a postfix:

| Patch | Method | Purpose |
|-------|--------|---------|
| Postfix | `DisablePickUpForAgentIfNeeded` | Re-enables pickup for agents that lost a melee weapon (with 500ms per-agent rate limit) |
| Transpiler1 | `ItemPickupTick` | Removes agent-targeting checks so troops pick up weapons regardless of target state |
| Transpiler2 | `SelectPickableItem` | Replaces last-element selection with closest-entity selection; makes melee weapons valid pickables; removes speed/distance checks |

## Current Status (as of 2026-05-28)

**The mod does not work in v1.4.5.** The Harmony patches never register — verified by:
- MapEventNullFix patch dump (302 battle-related patched methods at mission start, zero from `mod.bannerlord.pickupmeleeweapons`)
- No crash on startup (patches silently fail inside Harmony 2.4.2's internal exception handler)

### Fixes Applied So Far

1. **Removed `[SecurityCritical]` and `[HPCSE]`** — these break DynamicMethod patching in Harmony
2. **Safe `GetClosestPickableEntity`** — try-catch + `entity.IsValid` guard to prevent AVE on stale WeakGameEntity pointers
3. **500ms per-agent rate limit** in Postfix — prevents siege pickup flood (Stopwatch + Dictionary)
4. **Negative startIndex guard** — `Math.Max(0, i - 3)` in Transpiler2 (Vec3.Length loop) and `Math.Max(0, i - 2)` in Transpiler1 (GetTargetAgent loop); sentinel reset + `if (startIndex >= 0 && endIndex > startIndex)` guard before `RemoveRange`
5. **Transpiler try-catch** — both transpilers wrapped; on exception return original instructions and append to `%TEMP%\PMW_patch_error.txt`
6. **Switched from `PatchAll()` to explicit `PatchSafe()` calls** — each patch logged individually (`[PMW] OK:` / `[PMW] FAIL:`) to `%TEMP%\PMW_patch_error.txt`

### The Open Problem

Harmony 2.4.2's `PatchAll()` internally catches and swallows exceptions from individual type processors — the mod's patches fail silently. All three of our patches fail (including the simple Postfix with no transpiler logic), which suggests the failure is happening at **patch registration time** (before the transpiler even runs), not inside the transpiler body.

**Leading hypotheses:**
- The Postfix parameter injection fails: `____disablePickUpForAgent` (→ field `_disablePickUpForAgent`) or `___Agent` (→ inherited field from AgentComponent) can't be resolved by Harmony 2.4.2 in v1.4.5 context
- The transpiler method signatures are rejected by Harmony (private methods, or ILGenerator injection issue)
- A subtle type resolution issue when Harmony tries to build the patch method

## MapEventNullFix Integration

MapEventNullFix (`com.fix.mapeventnullfix`) has a `PickupMeleeWeaponsFix` component. When PMW is enabled and loaded, it applies a complementary patch. When PMW is NOT loaded (or crashes), it logs:
```
[MapEventNullFix] PickupMeleeWeaponsFix: PickupMeleeWeapons not loaded — skipping
```

MCM setting `EnablePickupMeleeWeaponsFix` in `MapEventNullFix_v1.json` is set to `false` (redundant with the dedicated mod when loaded).
